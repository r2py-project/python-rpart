### 1. Abstract

This session conducted a complete logical-equivalence audit of the `r2py_rpart` Python port against the original R `rpart` package, then fixed every bug identified by that audit plus a large number of additional bugs surfaced through live execution/rebuild/test cycles in the `r-to-python` conda environment, and finally diagnosed and repaired the one remaining known limitation — a broken `method=4` (user-defined split function) interpreter bridge — along with two further bugs (a process-crashing segfault and a heap-corrupting mutation bug) discovered while verifying that fix. The package was rebuilt and reinstalled via `pip install --no-build-isolation .` after every change and re-verified against the `tests/test_rpart.py` suite (12/12 passing) plus extensive manual smoke testing covering classification trees, regression trees, categorical predictors, pruning, prediction, plotting, cross-validation, and user-defined splits. The session ends with `r2py_rpart` functionally complete and logically equivalent to R `rpart` across all six audited subsystems, with all fixes confined to Python source files and exactly one C file (`c_entry_points/init_rpcallback_c.c`), per the user's explicit constraint that `r2py_rpart/src/` (the literal compiled-from-R C sources) must never be modified.

### 2. Methodology & Actions Taken

#### 2.1 Six-agent parallel audit

Before any code was modified, the CRAN `rpart` reference manual was fetched to enumerate the full public R API (`rpart`, `rpart.control`, `predict.rpart`, `print.rpart`, `summary.rpart`, `plot.rpart`, `text.rpart`, `prune.rpart`, `printcp`, `plotcp`, `snip.rpart`, `path.rpart`, `post.rpart`, `xpred.rpart`, `meanvar.rpart`, `labels.rpart`, `residuals.rpart`, `rsq.rpart`, `rpart.exp`, plus bundled datasets). Six `general-purpose` subagents were then dispatched in parallel (one stalled mid-run on the pruning/CP cluster and was resumed via `SendMessage`), each reading both the R source (`rpart/R/*.R`) and the Python port (`r2py_rpart/r2py_rpart/*.py`) plus the relevant C sources, covering:

1. **Core fit pipeline** — `rpart.py`/`rpart.R`, `rpart_matrix.py`, `na_rpart.py`, `model_frame_rpart.py`, `rpart_control.py`, the cffi bridge in `__init__.py`, and `c_entry_points/rpart_c.c` vs `src/rpart.c`.
2. **Callback/method dispatch** — `rpartcallback.py`, `rpart_anova.py`, `rpart_poisson.py`, `rpart_class.py`, `rpart_exp.py`, `c_entry_points/init_rpcallback_c.c`, `c_entry_points/interpreter_helpers_c.c`.
3. **Prediction** — `predict_rpart.py`, `pred_rpart.py`, `c_entry_points/pred_rpart_c.c`, `src/rundown.c`/`rundown2.c`.
4. **Pruning/CP/cross-validation** — `prune.py`, `prune_rpart.py`, `printcp.py`, `plotcp.py`, `xpred_rpart.py`, `snip_rpart.py`, `snip_rpart_mouse.py`, `c_entry_points/xpred_c.c`.
5. **Display/plotting** — `print_rpart.py`, `plot_rpart.py`, `text_rpart.py`, `post.py`/`post_rpart.py`, `rpartco.py`, `labels_rpart.py`, `rpart_branch.py`.
6. **Misc statistical utilities** — `formatg.py`, `importance.py`, `meanvar_rpart.py`, `path_rpart.py`, `residuals_rpart.py`, `roc_rpart.py`, `rsq_rpart.py`, `summary_rpart.py`, `zzz.py`.

Each agent reported findings with file:line citations and severities; results were independently spot-checked (e.g., the `ascontiguousarray`-after-`asfortranarray` column-major corruption claim was reproduced with a standalone NumPy byte-comparison script before being accepted) and synthesized into one consolidated report covering critical, high, and moderate-severity findings plus an inventory of subsystems verified correct.

#### 2.2 Comprehensive bug-fix pass

Following user approval, every audit finding was fixed directly in the Python sources, in priority order, with a `TodoWrite`-tracked checklist. After each fix (and again after each newly-discovered bug during verification), the package was rebuilt with `pip install --no-build-isolation .` inside `conda activate r-to-python` and re-tested. Fixes applied:

- **`r2py_rpart/__init__.py`** — replaced `np.ascontiguousarray(arr, dtype=...)` in `_int32`/`_float64` (which silently flattened Fortran-ordered 2-D inputs back to C-order, corrupting `xmat`/`nodes2`/`split2`/`csplit2`/`xdata2`/`xmiss2` for any matrix with >1 row and >1 column) with an order-preserving `np.asarray(..., order="K")` plus an explicit contiguity fallback; added explicit buffer-capacity checks (`nr*nc > cap`) before each `_rpart_c` output reshape so an undersized pre-allocation raises a clear `RuntimeError` instead of an opaque NumPy reshape error.
- **`rpart.py` / `model_frame_rpart.py`** — implemented real formula+data model-frame construction (`_build_model_frame`, a from-scratch R-style `"y ~ x1 + x2"` / `"y ~ ."` parser using regex, not patsy) to replace a `NotImplementedError` stub that made `rpart(formula, data=df)` — the documented call pattern — completely non-functional; implemented the `model_frame_rpart()` main branch (previously returned `None`) to re-invoke `rpart()` with the stored call's subset/method overridden, mirroring R's `model.frame.rpart.R` (which itself re-runs `rpart()`, a quirk preserved for fidelity); fixed the `method`/`weights`/`subset` partial-match helper to check exact matches before partial matches (matching R's `pmatch()` precedence); added a `keep` exception-propagation hook (see §2.3).
- **`rpart_matrix.py`** — removed an incorrect `patsy.dmatrix()`-based one-hot/dummy expansion of categorical predictors (rpart's C core natively handles multi-level categorical splits from a single integer-coded column, exactly as R's `rpart.matrix.R` does via `as.numeric(factor(x))`, not via `model.matrix`-style dummy coding); rewrote to assign one numeric column per term, with proper NA-propagating level-coding for both fresh string columns (sorted levels, matching R's `factor()` default) and pre-existing `pd.Categorical` columns (existing level order preserved, matching R's `as.numeric()` on an existing factor).
- **`na_rpart.py`** — fixed `Terms.attrs.get('response', 0)` (treating the package-wide `Terms` dict convention as an object with `.attrs`) to `Terms.get('response', 0)`.
- **Six files (`meanvar_rpart.py`, `printcp.py`, `snip_rpart.py`, `rsq_rpart.py`, `text_rpart.py`, `path_rpart.py`)** — fixed a class-identity check using the literal Python dunder `'__class__'` as a dict key (always `None`) to the actual key `rpart.py` sets, `'_rpart_class'`; this had made `prune`, `printcp`, `rsq_rpart`, `path_rpart`, `meanvar_rpart`, and `text_rpart` raise on every genuine fitted tree.
- **Systemic `_ylevels`/`_xlevels` key mismatch** — `predict_rpart.py`, `residuals_rpart.py`, `roc_rpart.py`, `summary_rpart.py`, `print_rpart.py`, `text_rpart.py`, `labels_rpart.py`, `xpred_rpart.py` all looked up `'ylevels'`/`'xlevels'` (or, in `predict_rpart.py`, a nonexistent `'_attr_ylevels'`) while `rpart.py` stores these as R-attribute-style keys `'_ylevels'`/`'_xlevels'`; all eight call sites corrected to the canonical key, restoring classification-tree reporting/prediction across the board.
- **`rpartcallback.py`** — converted an unbounded `_eval_result_keeper` list (one leaked C-heap `SEXPREC` per node/split evaluation, for the life of every `method=4` fit) into a single-slot holder that calls `free_sexp_helper` on the previous entry before storing a new one; added a `weakref.finalize`-driven `_CallbackSession` sentinel that releases the long-lived `sexp_y`/`sexp_w`/`sexp_x`/`sexp_n`/`_rho_sexp` allocations once the callback session is garbage-collected.
- **`importance.py`** — fixed an off-by-one in the surrogate-split row index (`spri_py[i]+ncompete[i]+{0..nsurr-1}` corrected to `{1..nsurr}`, matching R's 1-based `spri[i]+ncompete[i]+seq_len(nsurr[i])`), which had silently misattributed surrogate-split importance to the wrong predictor whenever `maxsurrogate>0` (the default).
- **`rpart_class.py`** — `parms['split']` is now coerced to `str()` before `pmatch`-style validation against `["gini","information"]` regardless of input type, matching R's `pmatch()` coercion semantics (previously, non-string `split` values bypassed validation entirely).
- **`roc_rpart.py`** — replaced a reference to `object$frame$splits`/`object$frame$yprob` (columns that do not exist on `frame` in either the current R source or the Python port — confirmed empirically via `Rscript` that the literal upstream R function silently operates on zero rows for every tree) with logic deriving `truth`/`leaf_probs` directly from the `yval2` block actually produced by `rpart()`, restoring a working, statistically sound implementation; also fixed `object.get('_class')`/`object.get('ylevels')` to the canonical `_rpart_class`/`_ylevels` keys.
- **`predict_rpart.py`** — implemented `_naresid()` (previously a documented no-op) to re-insert NA rows at the positions recorded in `na.action['indices']`, matching R's `naresid(object$na.action, pred)`; fixed `_yval2_matrix()` — `frame['yval2'].values` always returns a 1-D object array of per-row arrays (a pandas `Series.ndim` is always 1 regardless of contents), not a true 2-D matrix, so every `type='matrix'`/`'prob'` prediction silently failed; replaced with `np.array(frame['yval2'].tolist(), dtype=float)` at both call sites.
- **`formatg.py`** — `NaN` now formats as `"NA"` (matching R's `sprintf("%.Ng", NA)`) instead of Python's default `"nan"`.
- **`print_rpart.py`** — corrected `cat("n=", n[1L], "\n\n")`'s default `sep=" "` spacing (`"n= 80 \n\n"`) which the Python port had collapsed to `"n=80\n\n"`; fixed the same `yval2`-as-1-D-Series bug as `predict_rpart.py` for the `tfun(frame['yval2'], ...)` print-function call path.
- **`plot_rpart.py`** — root tick mark now uses `va='center'` (matching R's default-centered `text()`) instead of `va='bottom'`.
- **`plotcp.py`** — `_signif()` called `np.round(arr, decimals_array)` with a per-element `decimals` array, which NumPy's `round` rejects (`decimals` must be scalar); rewrote as an element-wise Python `round()` loop.
- **`xpred_rpart.py`** — fixed the same exact-before-partial `pmatch` precedence bug as `rpart.py`; fixed `parms` flattening (`np.array(list(parms.values()))` raised `ValueError` for classification `parms` dicts mixing a `prior` vector, a `loss` matrix, and a scalar `split` code — replaced with a ravel-and-concatenate loop matching R's `unlist()`); fixed two `fit['cptable'][...]`/raw-ndarray-style indexing call sites to convert the (now pandas-`DataFrame`-typed) `cptable` via `.to_numpy()` first.
- **DataFrame-vs-ndarray mismatches surfaced by live testing** — `rsq_rpart.py`, `plotcp.py`, `prune_rpart.py` (3 call sites), `labels_rpart.py` (3 call sites), and `snip_rpart.py` all performed NumPy-style `[:, i]`/`[mask, :]` positional indexing on `cptable`/`splits`, which `rpart.py` constructs as `pandas.DataFrame` objects, not raw arrays; all corrected to convert via `.to_numpy()`/`.iloc[]` first, with `prune_rpart.py`'s pruned-`cptable` reconstruction additionally fixed to preserve the original row labels via `.iloc[keep,:]` rather than building an unlabeled ndarray.
- **Missing cross-module imports** — `prune.py`, `post.py`, `print_rpart.py` (`prune_rpart`, `tree_depth`, `labels_rpart`), `prune_rpart.py` (`snip_rpart`, `importance`), `snip_rpart.py` (`snip_rpart_mouse`), `post_rpart.py` (`plot_rpart`, `text_rpart`), `plot_rpart.py`/`text_rpart.py`/`snip_rpart_mouse.py` (`rpartco`, `rpart_branch`, `string_bounding_box`), `labels_rpart.py`/`rpart_anova.py`/`rpart_class.py` (`formatg`), `path_rpart.py` (`labels_rpart`, `descendants`, `node_match`), and `xpred_rpart.py` (`rpart_matrix`, `rpartcallback`) all called functions defined in sibling modules without importing them, producing `NameError` on first use; all imports added, verified acyclic.
- **`zzz.py` / `rpartco.py` / `rpart_branch.py` / `plot_rpart.py` / `snip_rpart_mouse.py`** — `rpart_env` (R's package-level `new.env()` used to pass per-device plotting parameters between `plot.rpart`/`rpartco`/`rpart.branch`/`snip.rpart.mouse`) was declared via `global rpart_env` in four separate modules with no backing module-level definition anywhere, guaranteeing `NameError` on first plot call; defined once as a shared `dict` in `zzz.py` and imported by the other four; also fixed `rpart_branch.py`'s reference to a nonexistent `dev_cur()` function, replacing it with the same `'device' + str(1)` fixed-device-id convention already used consistently elsewhere in the port.
- **`snip_rpart.py`** — fixed a `where`-vector indexing convention bug (`id[x['where']]` indexed a 0-based array with 1-based `where` values; the rebuilt `where` was also written back 0-based, violating the 1-based convention `predict_rpart.py`/`residuals_rpart.py` rely on) by converting to/from 0-based consistently at the array boundary; fixed a pandas Copy-on-Write chained-assignment bug (`ff['ncompete'].iloc[newleaf] = 0` silently mutates a throwaway copy under pandas' CoW semantics, never updating `ff`) by switching to single-step `ff.iloc[newleaf, ff.columns.get_loc('ncompete')] = 0`; this CoW bug had been corrupting `importance()`'s post-prune surrogate/competitor accounting via stale `var`/`ncompete` values.
- **`summary_rpart.py`** — the function parameter is named `object` (matching R's `summary.rpart(object, ...)`), which shadows the Python builtin `object` type within the function's scope; three internal `np.array(..., dtype=object)` calls were silently passing the *fitted-tree dict* as a NumPy dtype spec, raising `ValueError: entry not a 2- or 3- tuple`; fixed via `import builtins` and `dtype=builtins.object`.
- **`text_rpart.py`** — same 1-D-Series-vs-2-D-matrix `yval2` bug as `predict_rpart.py`/`print_rpart.py`, fixed identically.
- **`tests/test_rpart.py`** — `test_rpart_raises_without_prebuilt_model` (which asserted the formula+data path raised `NotImplementedError`, codifying the bug as expected behavior) replaced with `test_rpart_formula_and_data_builds_model_frame` (asserts successful formula+data fitting) and `test_rpart_raises_without_formula_or_prebuilt_model` (asserts the genuinely-unsupported case — a non-string, non-DataFrame `formula`/`model` argument — still raises cleanly).

#### 2.3 Method=4 interpreter-bridge repair (final task)

The user explicitly requested a fix for the one remaining known limitation flagged in the synthesized audit: `method=4` (user-defined split functions) failed inside `init_rpcallback_c` with `RuntimeError: variable '(null)' not found`. Root-cause investigation proceeded by:

1. Grepping `src/rpart_callback.c`, `r_fake_headers/*.h`, and `c_entry_points/init_rpcallback_c.c` for the literal error string, tracing it to `compat_getVar`'s `error(_("variable '%s' not found"), ...)` call inside `src/rpart_callback.c:25` (off-limits for modification per the user's constraint).
2. Reading `c_entry_points/init_rpcallback_c.c` line-by-line and discovering that `rho_ptr`, `expr1_ptr`, and `expr2_ptr` — all opaque Category-E identity tokens that Python registers as dictionary keys (`_frame_registry[_rho_ptr]`, `_expr1_ptr`, `_expr2_ptr` in `rpartcallback.py`) *before* calling `init_rpcallback_c` — were each being re-wrapped via `make_opaque_sexp()`, a function that `malloc`s a **new** `SEXPREC` whose `->data` field merely points at the original pointer. `init_rpcallback()` (in the unmodifiable `src/rpart_callback.c`) stores and subsequently passes around this *new wrapper's own address* (`rho = rhox; expr1 = expr1x; ...`), not the original pointer Python had registered — so every later `findVarInFrame`/`eval` callback received an address that matched nothing in Python's lookup tables, regardless of correct registration.
3. Confirmed `SEXP` is a typedef for `struct SEXPREC *` (`r_fake_headers/SEXP.h`) and that neither `rho` nor `expr1`/`expr2` are ever dereferenced as real `SEXPREC` structs anywhere in this call path (only passed through opaquely to Python), so a direct `reinterpret_cast`-style pointer cast is semantically sufficient and was in fact the documented original intent ("`(SEXP cast internally)`" in the file's own parameter-map comment).
4. Fixed `c_entry_points/init_rpcallback_c.c`: removed the three `make_opaque_sexp()` calls for `rho_ptr`/`expr1_ptr`/`expr2_ptr` in favor of direct `(SEXP)` casts, and correspondingly removed their now-incorrect `free()` calls from the `FREE_INPUT_WRAPPERS()` macro (they are caller-owned pointers, not allocations made by this function). `s_ny`/`s_nr` (built via `make_int_scalar`, genuinely independent allocations) are unaffected.
5. Rebuilt and reproduced the original failure resolved; further testing with a synthetic three-function user method (custom `init`/`split`/`eval` implementing an ANOVA-equivalent split rule) surfaced a **segmentation fault** inside `usersplit()` → `rpart_callback2()`, traced via `python3 -X faulthandler` to a malformed (too-short) `direction` array returned by the test's own `split` function, combined with a pre-existing bug: `_py_eval()` in `rpartcallback.py` caught *all* exceptions (including its own length-validation `ValueError`s) and returned a raw null SEXP, which the unmodifiable C code dereferences unconditionally via `isReal()`/`LENGTH()`/`REAL()`, segfaulting the interpreter rather than raising a catchable error.
6. Hardened `rpartcallback.py`: `eval1()`/`eval2()` now pre-compute the C-side-expected return length (`1+numresp` for node evaluation; `2*(n-1)` continuous or `2*ncat-1` categorical for split goodness) *before* invoking user code, so that on any exception they can return a correctly-sized all-zero fallback array (satisfying the C side's length checks without crashing) while recording the exception in a new `rho["_pending_exception"]` single-element list; `_py_eval`'s outer catch-all was similarly hardened with a last-resort 1-element fallback. `rpart.py` was updated to declare `keep: dict[str, Any] | None = None` before the method-dispatch branch and, immediately after the `_rpart_c(...)` call returns, check `keep["_pending_exception"][0]` and re-raise it if set — ensuring a misbehaving user callback now produces a clean Python traceback instead of a process crash.
7. Re-running the corrected test end-to-end (`xval=0`, `minsplit=10`, synthetic two-class-mean ANOVA-equivalent splitter) produced a sensible 3-node tree (root split on `x1`, leaf means ≈ ±4.0 matching the synthetic data's design); re-running the deliberately broken (wrong-length `direction`) version now raises `ValueError: User 'split' function returned invalid direction` with a full traceback and exit code 1, instead of `Segmentation fault (core dumped)`.
8. A combined regression run (fit → `printcp` → `summary_rpart` → `prune` → `xpred_rpart`, all in one process) then surfaced a **third**, unrelated bug: `double free or corruption (!prev)`, isolated via bisection to `xpred_rpart(fit, xval=3)` called *after* `prune(fit, cp=0.5)` on the same `fit` object. Diagnosis: `prune_rpart()`/`snip_rpart()` mutated the input tree dict **in place** and returned the same object (`fit is pruned` evaluated `True`), violating R's copy-on-modify value semantics; the original `fit`'s cached `x`/`y` arrays (sized for the full dataset) became inconsistent with its now-pruned `frame`/`splits`/`csplit`, and `xpred_c`'s C-level buffer-size assumptions (computed from the inconsistent state) corrupted the heap. Fixed `snip_rpart.py` to copy `x` (top-level dict), `x['frame']`, `x['splits']`, `x['csplit']`, and `x['where']` independently at function entry, before any mutation, so neither `snip_rpart` nor (transitively) `prune_rpart` ever mutates a caller-visible object again.
9. Re-verified: `fit is pruned` now evaluates `False`; `fit['frame']` row count is unchanged after `prune()`; the fit → printcp → summary → prune → xpred sequence completes cleanly with no warnings and no crash; full `pytest tests/` suite (12/12) and the full classification/anova regression script both pass with exit code 0.

### 3. Key Findings & Results

- **Audit scope:** 6 parallel subagent passes covering every R/Python file pair in the public API plus all relevant C sources; findings ranged from a critical, package-wide column-major/row-major data-corruption bug in the cffi marshaling layer (affecting *every* multi-column model fit, predict, and cross-validation call) to cosmetic whitespace differences in `print.rpart` output.
- **Fix scope:** 37 files modified (36 Python, 1 C), +774/-218 lines per `git diff --stat`; 28 distinct bug classes fixed (per the session's `TodoWrite` checklist), spanning 4 critical, ~8 high-severity, and ~16 issues discovered only through live execution (missing imports, DataFrame/ndarray type mismatches, pandas Copy-on-Write semantics, a `dtype=object` parameter-shadowing bug, R-value-semantics violations).
- **Verification:** all fixes were validated by actually running the code (not just static review) — `pip install --no-build-isolation .` rebuild + `pytest tests/` (12/12 passing throughout) + targeted Python scripts exercising `rpart`, `predict_rpart` (all four `type=` values), `printcp`, `prune`, `summary_rpart`, `residuals_rpart`, `plot_rpart`, `text_rpart`, `plotcp`, `labels_rpart`, `path_rpart`, `xpred_rpart`, `snip_rpart`, `roc_rpart`, and `post_rpart`, on both classification (`method='class'`) and regression (`method='anova'`) trees, with categorical predictors, the `"y ~ ."` formula shorthand, and `method=4` user-defined splits.
- **Constraint compliance:** confirmed via `git status --short -- r2py_rpart/src/ r2py_rpart/c_entry_points/` that `r2py_rpart/src/` was never touched; the sole C-level change (`c_entry_points/init_rpcallback_c.c`, +28/-23 lines) was made in the explicitly user-sanctioned `c_entry_points/` directory.
- **Three additional bugs found only via dynamic testing of the method=4 fix**, none previously reported by the static audit: (1) the `init_rpcallback_c` pointer-identity bug itself; (2) a null-pointer-dereference segfault triggered by any malformed/erroring user split or eval callback; (3) heap corruption in `xpred_c` triggered by calling `xpred_rpart()` on a tree object that had previously been passed through `prune()`/`snip_rpart()`, due to in-place mutation aliasing.
