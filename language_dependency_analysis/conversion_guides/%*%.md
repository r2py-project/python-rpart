# Conversion Guide: `%*%` (Matrix Multiplication Operator) in R

---

## 1. Overview of `%*%` in R

`%*%` is R's infix matrix multiplication operator. It multiplies two conformable matrices or
vectors and returns their matrix product.

**Typical inputs:**

- Two matrices with compatible inner dimensions (an `m x k` matrix times a `k x n` matrix
  yields an `m x n` result).
- A matrix and a vector, or two vectors. When the arguments are not already two-dimensional,
  R automatically promotes them to a 1-row or 1-column matrix as required to make the
  dimensions conformable:
  - A vector on the left is treated as a **1 x n row matrix**.
  - A vector on the right is treated as an **n x 1 column matrix**.
  - When both arguments are plain vectors of the same length, the result is a **1 x 1 matrix**
    (the inner/dot product).

**Return value:** A `double` (or complex) matrix. Even when the mathematical result is a
scalar the return type is a 1 x 1 matrix, not a plain scalar.

**Key constraints:** The inner dimensions must match exactly. There is no recycling; a
dimension mismatch is a hard error.

## 2. Contextual Usage Analysis

All four CSV rows come from the same function `na.rpart` in
`/groups/jli9/Yufei/python-rpart/rpart/R/na.rpart.R`.

The function filters out rows from a data frame that are entirely missing (all predictors
missing, or the response missing). The `%*%` operator is used to **row-sum a logical
(boolean) matrix** by multiplying it against a column vector of ones:

```r
xmiss %*% rep(1, ncol(xmiss))
```

Here `xmiss` is the result of `is.na(x[-yvar])`, which produces a **logical matrix** with
one row per observation and one column per predictor variable. Multiplying by
`rep(1, ncol(xmiss))` — a numeric vector of ones whose length equals the number of columns
— effectively sums each row, yielding the count of missing values per observation. The result
is an **n x 1 matrix** of row-wise NA counts.

The same pattern applies to `ymiss` (line 13), which handles the case where the response
variable `y` is itself a matrix (multivariate response):

```r
ymiss %*% rep(1, ncol(ymiss))
```

There is exactly **one functionally distinct usage pattern** across all four rows: row-wise
summation of a logical/numeric matrix via multiplication by a ones vector. Lines 7, 12, and
14 all apply it to `xmiss`; line 13 applies it to `ymiss`. The comparison operators `<` and
`== 0` applied to the result are outside the scope of `%*%` itself.

**Data types involved:**

| Variable | R type | Shape |
|----------|--------|-------|
| `xmiss` | logical matrix (coerced to numeric for arithmetic) | `n_obs x n_predictors` |
| `ymiss` | logical matrix | `n_obs x n_ycols` |
| `rep(1, ncol(...))` | numeric vector | `n_cols x 1` (treated as column vector) |
| Result | double matrix | `n_obs x 1` |

## 3. Python Conversion Strategy

**Chosen library: `numpy`**

`numpy` is the direct equivalent of R's vectorized array operations. The idiomatic Python
replacement for `%*%` is either `numpy.matmul` or the `@` operator (which is syntactic sugar
for `numpy.matmul` on `ndarray` objects). Both handle 2-D arrays exactly like R's `%*%`
and support the same matrix-times-vector promotion semantics (a 1-D array on the right is
treated as a column vector, producing a 1-D result rather than a 2-D column matrix).

`math` module functions are not suitable here because they operate on Python scalars, not
arrays.

For the specific row-summation pattern found in this file, `numpy.sum(arr, axis=1)` is an
equally valid (and more explicit) alternative that avoids constructing the ones vector
entirely. Both approaches are shown below.

## 4. Step-by-Step Conversion Examples

### 4.1 Row-wise summation of a logical/numeric matrix via ones vector

**Locations:** `na.rpart.R` — function `na.rpart`, lines 7, 12, 13, 14.

**Original R context:**

```r
# xmiss is a logical matrix: n_obs rows x n_predictors columns
# rep(1, ncol(xmiss)) produces a numeric vector of length n_predictors
# The %*% operator promotes the vector to a column matrix and multiplies,
# yielding an n_obs x 1 double matrix (row-wise NA count).

xmiss <- is.na(x[-yvar])                            # logical matrix
row_na_count <- xmiss %*% rep(1, ncol(xmiss))       # n_obs x 1 matrix
keep <- row_na_count < ncol(xmiss)                  # logical: any non-NA predictor?

ymiss <- is.na(x[[yvar]])                           # logical matrix (multivariate y)
row_y_count  <- ymiss %*% rep(1, ncol(ymiss))       # n_obs x 1 matrix
all_y_ok     <- row_y_count == 0                    # logical: no missing response?
```

**Python equivalent (using `@` / `numpy.matmul`):**

```python
import numpy as np
import pandas as pd

# Assume `x` is a pandas DataFrame equivalent to R's data frame `x`.
# yvar is a 0-based integer column index (R's 1-based yvar converted).

# --- predictor missingness ---
x_pred = x.drop(columns=x.columns[yvar])           # drop response column
xmiss = x_pred.isna().to_numpy()                   # bool ndarray, shape (n_obs, n_pred)

ones = np.ones(xmiss.shape[1])                     # 1-D array of length n_pred
row_na_count = xmiss @ ones                        # 1-D array of length n_obs (float)
# Equivalent using np.matmul explicitly:
# row_na_count = np.matmul(xmiss.astype(float), ones)

keep_x = row_na_count < xmiss.shape[1]            # bool 1-D array

# --- response missingness (matrix response) ---
y_col = x.iloc[:, yvar]
if isinstance(y_col, pd.DataFrame) or (isinstance(y_col, np.ndarray) and y_col.ndim == 2):
    ymiss = pd.DataFrame(y_col).isna().to_numpy()  # bool ndarray, shape (n_obs, n_ycols)
    ones_y = np.ones(ymiss.shape[1])
    row_y_count = ymiss @ ones_y                   # 1-D array of length n_obs
    keep_y = row_y_count == 0
else:
    ymiss = y_col.isna().to_numpy()                # 1-D bool array
    keep_y = ~ymiss

keep = keep_x & keep_y
result = x[keep]
```

**Alternative (more Pythonic — skip the ones vector entirely):**

```python
import numpy as np

xmiss = x_pred.isna().to_numpy()                  # bool ndarray
row_na_count = np.sum(xmiss, axis=1)              # sum along columns, shape (n_obs,)
keep_x = row_na_count < xmiss.shape[1]
```

**Explanation:**

| R | Python | Notes |
|---|--------|-------|
| `xmiss %*% rep(1, ncol(xmiss))` | `xmiss @ np.ones(xmiss.shape[1])` | `@` calls `np.matmul`; a 1-D `ones` array on the right is treated as a column vector, giving a 1-D result rather than a 2-D column matrix. This differs from R, which returns an `n x 1` matrix — use `.reshape(-1)` or just rely on numpy broadcasting if a 1-D array is preferred. |
| `is.na(x)` → logical matrix | `x.isna().to_numpy()` → bool `ndarray` | Numpy treats `bool` as `0`/`1` in arithmetic, exactly like R's implicit coercion of logical to numeric in `%*%`. |
| `rep(1, ncol(xmiss))` | `np.ones(xmiss.shape[1])` | Both produce a ones vector whose length equals the number of columns. |
| Result: `n x 1` double matrix | Result: 1-D `float64` array of length `n` | R always returns a 2-D matrix; numpy's `matmul` with a 1-D right operand returns a 1-D array. For downstream comparisons (`< ncol(xmiss)`, `== 0`) this makes no practical difference because numpy broadcasting handles both shapes. |
| `ncol(xmiss)` | `xmiss.shape[1]` | Column count of a 2-D array. |

The more Pythonic `np.sum(xmiss, axis=1)` should be preferred when the only goal is
row-wise summation, as it makes intent explicit and avoids allocating the intermediate ones
vector.
