# Conversion Guide: `.checkMFClasses` (R to Python)

---

## 1. Overview of `.checkMFClasses` in R

`.checkMFClasses` is an internal R stats function that validates whether the variable types in a prediction model frame match the variable types recorded during model fitting. It is a type-safety guard used in `predict` methods to catch mismatches before feeding new data into a model.

**Signature:**

```r
.checkMFClasses(cl, m, ordNotOK = FALSE)
```

**Parameters:**

- `cl`: A named character vector mapping variable names to their type class strings (e.g., `"numeric"`, `"factor"`, `"ordered"`, `"character"`, `"logical"`, `"nmatrix.<k>"`, `"other"`). This is extracted from the model's terms object via `attr(Terms, "dataClasses")`.
- `m`: A model frame (a `data.frame` with a `"terms"` attribute) produced by `model.frame()` from the new prediction data.
- `ordNotOK`: A logical scalar (default `FALSE`). When `TRUE`, ordered factors and unordered factors are treated as distinct types. When `FALSE`, both are normalized to `"factor"` before comparison, making the check more permissive.

**Return value:**

Returns `NULL` invisibly when all checked variables match their expected types. Calls `stop()` with a descriptive error message if one or more variables have a different type in `m` compared to `cl`.

**Internal helper — `.MFclass(x)`:**

`.checkMFClasses` relies on the companion function `.MFclass`, which maps a single column of a model frame to one of these class strings:

| R column type | `.MFclass` result |
|---|---|
| logical vector | `"logical"` |
| ordered factor | `"ordered"` |
| unordered factor | `"factor"` |
| character vector | `"character"` |
| numeric matrix | `"nmatrix.<ncol>"` (e.g., `"nmatrix.3"`) |
| numeric vector | `"numeric"` |
| anything else | `"other"` |

**Permissive coercions applied before comparison:**

1. If `ordNotOK = FALSE`: both `"ordered"` entries in `cl` and `m` are normalized to `"factor"`.
2. Regardless of `ordNotOK`: if new data has `"ordered"` but the model was trained on `"factor"`, the new type is coerced to `"factor"` (predicting with an ordered factor when training used an unordered factor is always permitted).
3. If new data has `"factor"` but the model was trained on `"character"`, the new type is coerced to `"character"` (also always permitted).

## 3. Python Conversion Strategy

In Python, the translated `predict_rpart` function receives `newdata` as a `pandas.DataFrame`. The `dataClasses` attribute from the R terms object corresponds to a dictionary mapping column names to their expected type labels, which in the Python translation is stored in the fitted model object.

The Python equivalent is a hand-rolled validation function that:

1. Determines the "MF class" of each column in the new DataFrame using a helper that mirrors `.MFclass`.
2. Compares against the stored expected classes from the model.
3. Applies the same permissive coercions (ordered-to-factor, factor-to-character).
4. Raises a `ValueError` (the Python analogue of R's `stop()`) if a mismatch is found.

**Primary library:** `pandas` (for type inspection of DataFrame columns) with no numpy required, since the function performs no numeric computation — it is purely a type-checking guard.

```python
import pandas as pd
from typing import Optional


def _mf_class(series: pd.Series) -> str:
    """
    Python equivalent of R's .MFclass(x).

    Maps a single pandas Series (one column of a model frame DataFrame)
    to the same type-label string that R's .MFclass would produce.
    """
    dtype = series.dtype

    # logical / bool
    if dtype == bool or str(dtype) == "boolean":
        return "logical"

    # ordered categorical  (pandas CategoricalDtype with ordered=True)
    if hasattr(dtype, "ordered") and dtype.ordered:
        return "ordered"

    # unordered categorical / factor
    if str(dtype) == "category":
        return "factor"

    # character / object (string columns stored as object in pandas)
    if dtype == object or str(dtype) in ("string", "StringDtype"):
        return "character"

    # numeric matrix column: a column whose values are themselves arrays/lists
    # (R nmatrix.<k> arises from matrix predictors; rare in rpart usage)
    if dtype == object:
        # fallback — already caught above, but kept for clarity
        return "other"

    # numeric (int or float)
    if pd.api.types.is_numeric_dtype(dtype):
        return "numeric"

    return "other"


def check_mf_classes(
    cl: dict,
    m: pd.DataFrame,
    ord_not_ok: bool = False,
) -> None:
    """
    Python equivalent of R's .checkMFClasses(cl, m, ordNotOK).

    Validates that the variable types in prediction DataFrame `m` match the
    types recorded in `cl` at model-fitting time.

    Parameters
    ----------
    cl : dict
        Mapping of variable name -> expected type string, equivalent to
        R's attr(Terms, "dataClasses"). Valid type strings:
        "numeric", "factor", "ordered", "character", "logical",
        "nmatrix.<k>", "other".
    m : pd.DataFrame
        The prediction model frame (post model.frame equivalent). Only
        columns whose names appear in `cl` are checked; extra columns
        are ignored.
    ord_not_ok : bool, default False
        When True, ordered and unordered factors are treated as distinct
        types (the rpart usage always passes True).

    Raises
    ------
    ValueError
        If one or more variables in `m` have a different type than
        recorded in `cl`, mirroring R's stop() behaviour.
    """
    # Step 1: compute MF class for each column present in both cl and m
    common_vars = [v for v in m.columns if v in cl]
    if not common_vars:
        return

    new_classes = {v: _mf_class(m[v]) for v in common_vars}
    old_classes = {v: cl[v] for v in common_vars}

    # Step 2: apply permissive coercions (mirrors R's logic exactly)

    # 2a. ordNotOK=False: collapse "ordered" to "factor" in both old and new
    if not ord_not_ok:
        old_classes = {
            k: ("factor" if v == "ordered" else v)
            for k, v in old_classes.items()
        }
        new_classes = {
            k: ("factor" if v == "ordered" else v)
            for k, v in new_classes.items()
        }

    # 2b. Always: new is "ordered", old is "factor" -> treat new as "factor"
    for v in common_vars:
        if new_classes[v] == "ordered" and old_classes[v] == "factor":
            new_classes[v] = "factor"

    # 2c. Always: new is "factor", old is "character" -> treat new as "character"
    for v in common_vars:
        if new_classes[v] == "factor" and old_classes[v] == "character":
            new_classes[v] = "character"

    # Step 3: find mismatches
    wrong = [
        v for v in common_vars if old_classes[v] != new_classes[v]
    ]

    if len(wrong) == 0:
        return  # success — mirrors R's invisible(NULL)

    if len(wrong) == 1:
        v = wrong[0]
        raise ValueError(
            f"variable '{v}' was fitted with type \"{old_classes[v]}\" "
            f"but type \"{new_classes[v]}\" was supplied"
        )
    else:
        names_str = ", ".join(f"'{v}'" for v in wrong)
        raise ValueError(
            f"variables {names_str} were specified with different types "
            f"from the fit"
        )
```

**Explanation:**

- `_mf_class` mirrors R's `.MFclass` by inspecting `pandas.Series.dtype`. The key mappings are: pandas `bool` -> `"logical"`, ordered `CategoricalDtype` -> `"ordered"`, unordered `CategoricalDtype` -> `"factor"`, `object`/`string` dtype -> `"character"`, numeric dtypes -> `"numeric"`.
- `check_mf_classes` applies the three permissive coercions in the same order as R's source: (a) collapse ordered/factor when `ord_not_ok=False`, (b) always allow ordered-in-new when factor-in-old, (c) always allow factor-in-new when character-in-old.
- The function raises `ValueError` rather than R's `stop()`. A single-variable mismatch produces the same message format as R (`"variable 'X' was fitted with type ... but type ... was supplied"`). A multi-variable mismatch uses the plural form.
- The return value is `None` on success (equivalent to R's `invisible(NULL)`). The call site in `predict_rpart` discards this return value exactly as R does.
- `ord_not_ok=True` is hardcoded at the call site, matching the literal `TRUE` passed in the R source at line 16.
- The helper stubs `_has_terms_attr`, `_delete_response`, `_model_frame`, and `_get_data_classes` represent the Python translations of `attr(newdata, "terms")`, `delete.response()`, `model.frame()`, and `attr(Terms, "dataClasses")` respectively, which are handled by separate conversion guides.
