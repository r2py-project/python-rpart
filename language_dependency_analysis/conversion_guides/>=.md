# Conversion Guide: `>=` in R

## 1. Overview of `>=` in R

`>=` is R's built-in "greater than or equal to" comparison operator. It is a primitive binary operator that evaluates whether its left-hand operand is greater than or equal to its right-hand operand and returns a logical (`TRUE`/`FALSE`) value.

Key properties:

- **Fully vectorized:** When either operand is a vector (or matrix), R applies the comparison element-wise and returns a logical vector or matrix of the same shape. Scalar values are recycled to match the length of the longer operand.
- **Works on numerics, integers, characters, and factors** (for character/factor, lexicographic ordering is used).
- **NA-propagating:** If either operand is `NA`, the result is `NA`.
- Typical signature (conceptual): `a >= b` returns `logical` (scalar or vector/matrix depending on inputs).

## 2. Contextual Usage Analysis

### Source location

- **File:** `rpart/R/roc.rpart.R`
- **Line:** 8
- **Enclosing function:** `ss.compare` (a closure defined inside `roc.rpart`)

### Surrounding context

`ss.compare` is a two-argument helper closure defined on line 8:

```r
ss.compare <- function(a, b) a >= b
```

It is immediately used on line 13 as the binary function (`FUN`) argument to `outer`:

```r
pred.np <- outer(cutoffs, object$frame$yprob[endnodes, 2L], ss.compare)
```

`outer(X, Y, FUN)` computes the generalized outer product: it calls `FUN(X[i], Y[j])` for every combination of elements from vectors `X` and `Y`, producing a matrix of dimensions `length(X) × length(Y)`.

- `cutoffs` is a numeric vector of probability thresholds (length ~ number of unique predicted probabilities + 2).
- `object$frame$yprob[endnodes, 2L]` is a numeric vector of predicted class-2 probabilities at each terminal node.
- The result `pred.np` is a **boolean matrix** of shape `(length(cutoffs), length(endnodes))`. Each cell `[i, j]` is `TRUE` when `cutoffs[i] >= yprob[j]`, i.e., the cutoff is at least as large as the predicted probability for that node.

The matrix is then used as a boolean index to build a sensitivity/specificity table across all cutoffs, forming the backbone of the ROC curve computation.

**Pattern summary:** `>=` is used here in a purely numeric, vectorized context wrapped as a named function so it can be passed as a higher-order argument to `outer`. The comparison is always between floating-point scalars (broadcast pair-wise), and the return type is always a boolean matrix.

## 3. Python Conversion Strategy

**Chosen library: `numpy`**

R's `>=` is natively vectorized. The direct Python equivalent for numeric arrays is `numpy`'s `>=` operator (or equivalently `numpy.greater_equal`), which performs element-wise comparison across arrays of any shape and returns a boolean `ndarray`.

For the specific `outer`-product pattern (`outer(X, Y, ss.compare)`), the exact NumPy equivalent is `numpy.greater_equal.outer(X, Y)`, which computes the pairwise `>=` comparison between every element of two 1-D arrays and returns a 2-D boolean matrix — identical semantics to R's `outer(X, Y, function(a, b) a >= b)`.

`math.isclose` or Python's built-in `>=` on plain scalars would not handle the vectorized/matrix context here and are therefore not appropriate.

## 4. Step-by-Step Conversion Examples

### 4.1 `>=` as a Standalone Vectorized Comparison

**Locations:** `roc.rpart.R` — `ss.compare` (line 8)

**Original R context**

- `a` and `b` are numeric scalars, vectors, or matrices.
- Return type: logical scalar, vector, or matrix of the same shape.

```r
# General form
ss.compare <- function(a, b) a >= b

# Scalar example
ss.compare(0.6, 0.5)   # TRUE
ss.compare(0.4, 0.5)   # FALSE

# Vectorized example
ss.compare(c(0.2, 0.5, 0.8), 0.5)   # FALSE TRUE TRUE
```

**Python equivalent**

```python
import numpy as np

def ss_compare(a, b):
    return np.greater_equal(a, b)

# Scalar example
ss_compare(0.6, 0.5)   # True
ss_compare(0.4, 0.5)   # False

# Array example
ss_compare(np.array([0.2, 0.5, 0.8]), 0.5)   # array([False,  True,  True])
```

**Explanation**

- `numpy.greater_equal(a, b)` is the functional form of `a >= b` in NumPy and handles scalars, 1-D arrays, and N-D arrays identically.
- When `a` or `b` is a plain Python scalar, NumPy still returns a NumPy scalar (which behaves like a Python `bool` in boolean contexts), so no special-casing is needed.

### 4.2 `>=` Inside `outer` — Pairwise Threshold Matrix

**Locations:** `roc.rpart.R` — `roc.rpart` (line 13, uses `ss.compare` defined at line 8)

**Original R context**

- `cutoffs`: numeric vector of length `C` (probability thresholds).
- `yprob`: numeric vector of length `N` (predicted probabilities at terminal nodes).
- Return type: logical matrix of shape `C × N`.

```r
ss.compare <- function(a, b) a >= b
pred.np <- outer(cutoffs, yprob, ss.compare)
# pred.np[i, j] is TRUE when cutoffs[i] >= yprob[j]
```

**Python equivalent**

```python
import numpy as np

# cutoffs: 1-D numpy array of shape (C,)
# yprob:   1-D numpy array of shape (N,)

pred_np = np.greater_equal.outer(cutoffs, yprob)
# pred_np[i, j] is True when cutoffs[i] >= yprob[j]
# Shape: (C, N), dtype: bool
```

**Explanation**

- `numpy.greater_equal` is a `numpy.ufunc`. All NumPy ufuncs expose an `.outer` method that computes the pairwise operation between every element of two arrays, exactly mirroring R's `outer(X, Y, FUN)`.
- The result is a 2-D boolean `ndarray` of shape `(len(cutoffs), len(yprob))`, matching R's `length(cutoffs) × length(endnodes)` logical matrix.
- An alternative spelling that produces the same result by broadcasting is `cutoffs[:, np.newaxis] >= yprob[np.newaxis, :]`, which may be more readable in some contexts.

```python
# Alternative broadcasting spelling (equivalent result)
pred_np = cutoffs[:, np.newaxis] >= yprob[np.newaxis, :]
```

- NumPy uses 0-based indexing whereas R uses 1-based indexing; when translating the downstream indexing of `pred.np` (e.g., `pred.np[i, ]`) remember to subtract 1 from any hard-coded R index (e.g., `pred.np[1L, ]` in R becomes `pred_np[0, :]` in Python).
